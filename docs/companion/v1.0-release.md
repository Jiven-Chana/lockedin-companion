# LockedIn v1.0: release note and test checklist

**Tag:** `lockedin-v1.0` · **Built from:** [`v1.0-plan.md`](v1.0-plan.md) · **Decisions:** [`DECISIONS.md`](DECISIONS.md) V-19 to V-31

v1.0 fixes what was broken in v0.1. Nothing is redesigned and nothing is packaged: the polish is v2.0 ([`v2.0-direction.md`](v2.0-direction.md)) and the desktop app is v3.0.

---

## 1. Run it

```bash
cd ~/PycharmProjects/LockedIn && git checkout main && git pull
nvm use 26 && npm ci
npm run build
LH_DATA_DIR=$PWD/runs/v1 npx next start -p 3000
```

Then open `http://localhost:3000`.

- **Use a fresh folder** (`runs/v1` above). Your earlier folders hold uploads whose PDF was never saved (see S-2 below), so their pages can't be shown. Uploading the same files again takes a minute.
- **Stop any other LockedIn server first.** Only one can use port 3000.
- For the facilitator's buttons (the phone test in section 3), add `COMPANION_DEMO=1` before `npx`.

## 2. What was fixed

Each line is one issue from [`v1.0-issues.md`](v1.0-issues.md).

### Teaching sessions
- **T-1** A session on your own notes now reaches question 1. If the teacher sets its plan and stops, LockedIn asks it once for the question.
- **Found while checking v1.0:** a session could end early ("2 of 5 answered, and the teacher wrapped up"). The model's turn after an answer sometimes comes back empty, and the "Next question, please." that recovers it only worked once per session. It now works once per stop.
- **T-6** A failed session says what happened ("The teacher didn't ask a question.", "Your AI isn't connected.") and **Try again** works. When the lecture has a question bank, **Use practice questions** runs it without the AI.
- **T-3** Long decks: the teacher always saw the whole 79-slide deck (that failure was T-1). Study packs no longer lose the last pages of long notes, and the slide panel hides its row of dots above 20 pages.
- **T-4** Study packs retry (after 10, 30 and 90 seconds), wait while your AI connection is down, and pick up on their own after a restart. They always ran one at a time; one dropped request used to fail every pack behind it.
- **T-5** A unit with under 500 characters of text can't be saved, and says why. The failing "one-page unit" was the words "Week 8" typed into the paste box.

### Slides and notes
- **S-1** The slide panel moves through a unit's own pages ("Page 18 of 38"). "No material" no longer appears for uploaded notes.
- **S-2** The panel and the lecture's Slides tab show the real PDF page. The uploaded PDF was never being kept (every stored file was 0 bytes); it is now.
- **S-4** The drop zone says several files are fine. Packs start on their own (they always did; they only needed starting by hand after failing). An unknown week reads "Week not set", with a one-tap **Set week**.

### Progress and settings
- **V-1** No "Week 0". Status pills stay on one line. Every Progress card is the same card, with the module's colour as a dot.
- **V-2** Once you save your own material or connect a real calendar, the sample lectures are hidden. Nothing is deleted.
- **C-2** `localhost:3000` opens LockedIn.

### Phone
- **P-1** An iPhone opening the pairing link gets three steps with pictures and a sample question. The Home Screen app opens already paired, says "✓ Installed" and asks for notifications. The laptop shows the phone arriving instead of "Waiting for your phone…".
- **P-4** The demo clock only applies in facilitator mode, so a leftover offset can't shift a real run.

### Calendar
- **K-1** A calendar event titled due, deadline, assignment, coursework, submission or hand-in is never a lecture, so it never sends "…just finished".
- **K-2** The Birmingham timetable test is kept.

### Platform, log and build
- **D-1** "Checking your AI connection…" gives up after 15 seconds with **Try again**.
- **D-2** Next.js 16.4.6: the security warning on every start is gone.
- **X-1** The event log counts each action once (`session_opened`, `checkin_shown`, `target_changed`, `engine_ready`, saving material).
- **N-0** The server build no longer contains `runs/` (test participants' logs), and refuses to finish if any participant data is left in it.

### Not in v1.0
- **To v2.0:** Teach and Practice as two modes (T-2), teaching by idea (T-3), notes versus slides (S-3), progress as a picture (V-3), a short Me (C-1).
- **To v3.0:** the desktop app (N-1 to N-3), the relay on a team account (P-3), code clean-up (X-2 to X-5), and one name and one shape per event (the rest of X-1).

## 3. Test checklist

### Progress and Me
- [ ] Progress has no "Week 0", no pill on two lines, and every module card looks the same. *(V-1)*

### Phone (after the relay is redeployed)

### Calendar

## 6. v1.0.1 (24 Nov, after Jiven's first test)

Tag `lockedin-v1.0.1`. Two plain bugs from his test of v1.0 on his own six modules:

- **The iPhone still said "Open the link or QR code from your laptop" after Add to Home Screen.** The relay had not been redeployed, so the phone was running the v0.1 phone app, which loses its pairing on install (P-1). The relay is now deployed with the v1.0 phone app. **To retry:** delete the LockedIn icon from the Home Screen, then on the laptop go to Me → Phone → Show the pairing code and scan it again.
- **A diagram showed a mermaid syntax error.** 1 of his 63 explainer diagrams had a label with brackets in it (`D[None: calculate d(A)]`). Flowchart labels are now quoted before a diagram is saved, read or drawn (`safeMermaid`), so existing packs are fixed without rewriting them. Checked by drawing all 78 of his diagrams with the real mermaid library: none fails, and none changed size.

The other three points from that test are design changes and open v2.0 ([`v2.0-direction.md`](v2.0-direction.md), "From Jiven's test of v1.0"):
- concept maps come out large and tangled;
- Progress lists every timetabled lecture (59 across his modules);
- a chapter of notes can only be given one week, not a range.
