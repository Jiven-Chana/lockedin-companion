# LockedIn v1.0: the fix plan

**Status:** approved by Jiven, 24 Nov 2026. Decisions V-19 to V-31 in [`DECISIONS.md`](DECISIONS.md).

**What v1.0 is (decided 24 Nov, Jiven):** every broken thing in [`v1.0-issues.md`](v1.0-issues.md) is fixed, so there is a stable base to test. Nothing is redesigned and nothing is packaged.

| Version | What it is |
|---|---|
| **v1.0** | Fix what fails, misleads or corrupts data. Released as a tag, tested from a production build |
| **v2.0** | The polish stage ([`v2.0-direction.md`](v2.0-direction.md)): Learn and Practise, progress as a picture, a short Me, notes split by idea, teaching by idea |
| **v3.0** | The desktop app (Mac and Windows), code clean-up, any flow polish left, and bugs found in v2.0. Not specified yet |

**Release route (decided 24 Nov):** v0.1 was merged into `main` as it stood and tagged `lockedin-v0.1` (done). v1.0 is built on `feat/v1.0` with its own PR, merged when CI is green, and tagged `lockedin-v1.0`.

## 1. What the investigation corrected

Each issue's cause was re-checked against the code and against the two data folders (`runs/try`, `runs/mine`). Five causes in the issue list were wrong or incomplete. The fixes below follow the corrected causes.

| Issue | The list said | What is actually true |
|---|---|---|
| **T-4** packs fail together | Five packs ran in parallel on one sign-in | Packs already run one at a time. One ChatGPT request failed in the middle of pack 2. The model list then failed to reload, so packs 3 to 6 failed within 40 ms of each other. Nothing retried. The "same second" was the time they were queued |
| **T-3** long decks | The teacher may only see the start of the deck | The 79-slide deck is about 5,500 tokens, under the 8,000 budget, so the teacher saw all of it. That session failed because of T-1. The real long-material bug is in study packs, which cut text at 48,000 characters and lose the last pages |
| **T-5** one-page unit | A one-page unit can't get a pack | The unit was the words "Week 8" typed into the paste box, whose placeholder reads "Week 1: …" |
| **S-2** raw slide text | The panel shows extracted text; show the PDF page instead | True, and there is a second bug underneath: **the uploaded PDF is never kept**. Every stored `slides.pdf` is 0 bytes, because the PDF reader empties the upload before it is written to disk |
| **S-4** packs started by hand | Each pack must be started by hand after saving | Packs already start on their own after saving. They needed starting by hand only because they had failed (T-4) |
| **K-1** Canvas deadlines | Zero-length events become lectures | Zero-length events are already dropped. The gap is a short event with a length, such as "HCI coursework due" 23:00 to 23:59 |
| **N-0** build output | Add `runs/**` to the tracing excludes | That pattern also removes four files the OpenAI library needs. The safe fix removes the folders after the build and then refuses to continue if any are left |
| **P-1** phone install | The install page is unclear | Also: an iPhone gives a Home Screen app its own storage, so the pairing is probably lost on install, and the laptop keeps saying "Waiting for your phone…". This needs your iPhone to confirm |

**T-1 is confirmed as written.** In both failed sessions the teacher set its plan, wrote one sentence ("The plan is set. We'll start by…") and ended its turn. The prompt already forbids this, so a prompt change is not enough. "Try again" on that screen also does nothing today.

## 2. The work, in order

Blockers come first. Each step is its own commit on `feat/v1.0`, with its tests written first.

### Step 1. Sessions always reach question 1 (T-1, T-6)
- **Safety net before question 1.** If the teacher ends its turn without asking, LockedIn sends "Next question, please." once and keeps waiting. This is the same rule as between questions (your 23 Nov decision), and it is logged as `teacher_nudged`.
- **"Try again" works.** On a session that never asked, it re-sends the request instead of doing nothing.
- **Failure screens say what happened** and offer one main action. Wording in section 3. The heading "Something got stuck" goes.
- **Where:** `engines/learnharness.ts`, `service.ts` (sessions), `policy.ts` (wording), `session.tsx`.
- **Tests:** a teacher that stops after its plan is asked once and then asks question 1; a second stop gives a plain error; "Try again" recovers it; two overlapping page updates send only one request.

### Step 2. The slide panel shows your real pages (S-1, S-2, T-3)
- **Keep the PDF.** Write the file to disk before reading it, so `slides.pdf` holds the real bytes. "Has a PDF" means a file with content.
- **Page numbers.** The panel moves through the unit's own pages ("Page 18 of 38"), so "No material" no longer appears for uploaded notes. Numbers are not renumbered, because citations, packs and maps rely on them.
- **The real page.** For an uploaded PDF, the panel and the lecture's slides tab show the page as an image. The laptop draws it with the engine's existing PDF renderer and keeps a copy, so it is drawn once. The extracted text stays for search and for the AI.
- **No PDF, no image.** The bundled sample lectures and pasted text have no PDF, so they keep the text view.
- **Long decks.** The row of dots under the panel is hidden above 20 pages.
- **Where:** `materials.ts`, `service.ts` (materials), a new route `materials/[lectureId]/pages/[n]`, `lh-port.ts` (the renderer call), `slides.ts` (a page-navigation helper), `session.tsx`, `lecture.tsx`.
- **Tests:** the stored PDF has the uploaded bytes even when the reader empties its input; navigation over pages 18 to 38; the page route returns an image for an uploaded unit and "not found" for a sample one.

### Step 3. Study packs survive a bad minute (T-4, T-5, T-3, S-4)
- **Retry.** A failed stage is tried again up to 3 times, waiting 10, 30 and 90 seconds.
- **Wait, don't burn the queue.** If the AI connection is down, the packs behind it stay queued. They no longer fail one after another.
- **A "queued" state**, shown as "Waiting its turn".
- **Pick up after a restart.** Packs that were queued or interrupted resume on their own when the app next starts with the AI connected.
- **Plain wording** for every pack state and failure (section 3). The raw "chatgpt catalog has no model…" text is never shown.
- **Long notes.** Packs trim long text evenly across pages instead of cutting off the end.
- **Too little to study from.** A unit with under 500 characters of text can't be saved; the row says why. The paste box placeholder becomes "Paste your notes here".
- **Upload wording.** The drop zone says "Drop all your slides and notes here. Several files at once is fine."
- **Where:** `study-pack.ts` (core and server), `policy.ts` (`PACK_RULES`), `lh-port.ts` (a typed "connection unavailable" error), `units.ts`, `service.ts`, `lecture.tsx`, `library.tsx`, `material-upload.tsx`.
- **Tests:** fail once then succeed gives a ready pack; a connection that stays down leaves later packs queued; a restart resumes them; the stored error is the plain wording; the too-short rule.

### Step 4. No "Week 0", no demo content beside yours (S-4, V-1, V-2)
- **"Week not set"** wherever a week is unknown, from one shared helper. Next to it, a one-tap "Set week" on the unit (a new small route, because a unit's week can't be changed after saving today).
- **Progress layout.** Status pills never wrap. Every module card uses the same neutral card, with the module's colour as an accent only.
- **Sample content.** Once you save a real upload or import a real calendar, the sample lectures are hidden. Nothing is deleted, and the facilitator's scenarios bring them back.
- **Where:** a week-label helper in `src/core/companion`, `progress.tsx`, `lockedin.css`, `library.tsx`, `lecture.tsx`, `timetable.ts`, `service.ts`.
- **Tests:** the helper's table; saving a unit on a sample profile hides the sample lectures; setting a unit's week.

### Step 5. Smaller fixes (C-2, D-1, P-4, K-1, K-2)
- **`/` opens LockedIn.** `localhost:3000` redirects to `/app`. The engine's own pages stay reachable at `/chat/new` (its Settings open from there) and `/chat/<id>`.
- **"Checking your AI connection…"** gives up after 15 seconds with "Try again", and Me makes one request instead of two.
- **The demo clock** applies only when `COMPANION_DEMO=1`, so a leftover offset can't skew a real run.
- **Deadlines are never lectures.** A calendar event whose title says due, deadline, assignment, coursework, submission or hand-in is treated like a lab: it is not a lecture and gets no "just finished" nudge. A test also pins that zero-length events are dropped, and the Birmingham test (K-2) stays.
- **Where:** `next.config.ts` (an engine file, so one line in `NOTICE`), `connect.tsx`, `voice-section.tsx`, `default.ts`, `timetable.ts`.

### Step 6. The event log counts each action once (X-1)
- `session_opened` is logged once per open, decided from the fresh record.
- `checkin_shown` is logged only when the check-in is shown, not on each answer or phone replay.
- Saving material logs `materials_saved` only.
- A target changed in the check-in logs `target_changed {via: "checkin"}` and no extra `settings_changed`.
- `engine_ready` is logged when the AI becomes ready, not on every restart.
- **New test:** one user action produces exactly one event.
- **Not in v1.0:** renaming events and giving each type one shape. See choice 12.

### Step 7. Build safety (N-0, D-2)
- **N-0.** `scripts/build-server.mjs` removes `runs`, `tests`, `docs` and `relay` from the build output, then refuses to finish if `runs/`, `data/` or any event log is still in it.
- **D-2.** Next 16.4.3 → 16.4.6 (the security patch), done last, with the full test suite and the packaging tests as the gate. If the gate fails it is reverted and moves to v3.0.

### Step 8. Phone install (P-1)
- **A guided install screen** on iPhone: the Share button, then "Add to Home Screen", with pictures.
- **The pairing survives the install.** The Home Screen app opens already paired.
- **A check that it worked:** "✓ Installed. Now tap Allow notifications."
- **A sample question** to try on the page. It sends nothing to your laptop.
- **The laptop knows the phone arrived** as soon as the page opens, instead of "Waiting for your phone…".
- Android and desktop browsers skip the install step, as today.
- **Where:** `relay/web/*`, `relay/src/*` (a per-pair app manifest), `tests/companion-relay*.test.ts`.
- **Needs you:** the relay must be redeployed to your Cloudflare account (I will ask before deploying), then one test on your iPhone.

### Step 9. Prove it and release
- **Real-engine run** on your ChatGPT sign-in, in a production build: 3 sessions of 5 questions on each of two real lectures (Game Theory intro, Neural Computation), plus two study packs. Results go in `CHECKPOINT.md`.
- **Docs:** `VERSIONS.md` (v0.1 as shipped, v1.0), `DECISIONS.md`, `API.md`, `NOTICE`, and a release note, `v1.0-release.md`: each fix in one line, plus the checklist you test against.
- **Release:** PR `feat/v1.0` → `main`, CI green, squash merge, tag `lockedin-v1.0`.

## 3. Choices made for you

These follow the directions in the issue list. Approved on 24 Nov and recorded in `DECISIONS.md` (V-21 to V-31).

| # | Choice | Why |
|---|---|---|
| 1 | **Slides:** the real PDF page, with the text view only where no PDF exists. No AI-written summary in v1.0 | Both docs say "show the real page". Summaries are a v2.0 visual decision |
| 2 | **Before question 1:** one automatic "Next question, please.", then a plain error with a working "Try again" | Same rule you chose on 23 Nov for between questions |
| 3 | **Pack retries:** 3 tries, waiting 10 s, 30 s, 90 s; packs behind a dead connection wait | A dropped connection usually returns within two minutes |
| 4 | **Smallest unit:** 500 characters of text | A pack needs at least 2 ideas and 12 questions. 500 characters is about one short paragraph; a single real slide page averages about 270 |
| 5 | **Unknown week:** "Week not set" with a one-tap "Set week" | The issue list's direction (S-4) |
| 6 | **Progress cards:** neutral card, module colour as an accent | Today HCI's colour equals the app's default colour, so it looks unpainted beside the others |
| 7 | **Sample lectures:** hidden automatically once real content exists, never deleted | No extra question to answer; the facilitator can still bring them back |
| 8 | **`/` always goes to `/app`**, not only in the desktop app | The engine's home screen confused real use; its pages stay reachable by address |
| 9 | **Deadline words:** due, deadline, assignment, coursework, submission, hand-in. Not "quiz" or "test", which can be taught sessions | Stops the midnight "HCI just finished" nudge. A real deadlines feature is later |
| 10 | **Phone:** a guided web install, not a native app | Matches the v2.0 doc; a native wrapper is only considered if this fails on a real phone |
| 11 | **Next.js patch:** included, last, behind the test gate | It is a security patch and its warning interrupts every start |
| 12 | **Event log:** fix the double counts now; renaming events and unifying their shapes moves to v3.0 | Renames two days before the 26 Nov test could break Lekan's analysis, and they are clean-up, not a bug |

**Failure wording** (all in `policy.ts`):

| When | The screen says | Main action |
|---|---|---|
| The teacher never asked | "The teacher didn't ask a question." | Try again |
| Question 1 took too long | "Writing the question took too long." | Try again |
| The AI didn't answer | "Your AI didn't answer. Check your internet connection." | Try again |
| No AI connected | "Your AI isn't connected." | Connect |
| Anything else | "Something went wrong on our side." | Try again |

Under the main action: **Use practice questions** (when the lecture has a question bank) and **Pick another lecture**.

| Pack state | The lecture page says |
|---|---|
| Queued | "Waiting its turn." |
| Retrying | "Your AI was busy. Trying again in 30 seconds." |
| Waiting for the connection | "Waiting for your AI connection." |
| Failed after retries | "Your AI didn't answer after 3 tries." with **Try again** |
| Too short | "There's too little here to study from. Add more material." |
