# v3.1 plan: Learn that teaches

Approved by Jiven on 28 Nov 2026. This plan is the design for v3.1; anything it does not cover is a question for him, not a guess.

## 1. Where it came from

Jiven ran first-run setup and a Learn session on v3.0.1 with a fresh data folder and his own slides, and wrote down what was wrong. In his words:

- "I cant upload multiple pdfs… I cant upload htmls or mds."
- A question asked before anything was taught: "In the lecture's temperature example, which estimate minimises the total absolute error for measurements 17, 19, and 24? like how am i supposed to know? The probe stage is a bit fucked."
- "We should ask the user what their intention is for the session. If they dont know give suggestions, if they do know let them type out, then enter an optional probe stage, from this stage we figure out their current knowledge in actionable blocks from basic to advanced then we generate the plan off that."
- "I dont have the oppourtunity to attach say a worked solution to the learn session chat so the AI can walk me through the questions to get me to a stage where I can actually attempt an augmentation of the question myself."
- "Some of the practise Qs are really fucking easy and some are just not really well written and feels like AI slop rather than the real learning loop we researched."
- "The first learn session the AI only has access to week 1."
- "The form of question being MCQs is not great for the learn session, it should be more organic… give harder Qs."
- "The visualisation agent is not great… I dont want my users just sitting there waiting for AI… slides dont auto switch with new questions. I have 120+ page slides to flick through… say im doing a module where the notes are in A4, how do you handle that?"
- "Remember the learn stage is to actually learn. Not just be pretty."

## 2. What the code did (read on 28 Nov, v3.0.1)

| He saw | Cause in the code |
|---|---|
| Several PDFs fail | Every upload passes a 26 MiB limit on the whole request (`next.config.ts`, `proxyClientMaxBodySize`), and Next cuts a larger body off silently. His Neural Computation PDFs total about 43 MB; his fresh run recorded 14 uploads of one file each. Not reproduced: this is what the code and his records imply |
| One bad file loses the batch | `CourseMaterials.propose` converts files one after another and throws on the first failure |
| `.html` refused | No path for it (`materials.ts`, `toPages`). `.md` works in setup and the Library; a lecture's own page takes one PDF only |
| The opening question could not be answered | LockedIn's prober prompt says "Do not ask what they want to learn" and "Build every question from the slides and the concept map only", and uses the engine's marked multiple-choice tool. The engine's own prober, which LockedIn replaced, pins down the goal and tests each needed idea until it finds where knowledge stops |
| "Only has access to week 1" | A session is given one unit (or this week's). The tutor is told "Read only SLIDES FILE paths from the first message" and is never given the module's other units |
| Checks are multiple choice | Marked written answers (`explain`, `recall`) exist in the engine and are switched off in LockedIn's seed settings. The plan only moves on a tagged `quiz` |
| No attachments | LockedIn's line to the tutor sends text only. The engine accepts images in a chat turn |
| Practise questions easy or badly written | One call on the cheap model with a 15-line prompt that says "Mix difficulties, mostly 1 and 2" and "answerable from the slides alone", a 90-character cap on the question, and format checks only. A lecture's "Practise this", study blocks and the hand-off always take the five easiest of the unit |
| The slide panel does not follow | In Learn a tutor question carries no slide; the panel follows the lowest slide cited in the step, and once the student picks a slide it never follows again |
| Waiting | Nothing is streamed: the screen polls and shows "Your tutor is writing…" |
| Visuals | The engine's picture and demo makers are wired in but shown in the reading column, with no enlarge |
| A4 notes | Every PDF page is one "slide" (known since v1.0: S-3, "Lecture notes are treated like slides") |

**Not a cause, measured.** The reading budgets do not starve the AI: on his fresh run, question writing sees 98 to 100% of every unit's text and the tutor 68 to 100%. His Neural Computation slides carry about 290 characters of text a page. An earlier claim in this session that the AI saw "fragments" was wrong.

## 3. The constraint: AI usage

Jiven, 28 Nov: "the ai usage is a massive constraint. uni students are likely on lower tier subscriptions." So:

- Reading budgets stay exactly as they are (`LEARN_RULES.slideTokenBudget`, `PACK_RULES`).
- Practise questions stay on the cheap model, one call per unit.
- Nothing rewrites existing questions unless the student presses a button.
- The "what do you want" step is plain screen with no AI call. Skipping the check saves a call.
- Written checks use the same number of tutor turns as multiple choice did.
- An attachment is read as text where it has text, and as a picture only where it does not.
- Every real-AI check during this build is counted and kept few.

## 5. Part A: repairs

1. **Uploads.** Each file travels in its own request, so the total no longer matters. A file that cannot be read is reported by name and the others are kept. `.html` and `.htm` are accepted (the engine's own HTML-to-Markdown conversion). A lecture's own page takes PDF, Markdown, text and HTML.
2. **The whole module in Learn.** The opening message lists every unit of the session's module (week, title, its ideas, its slides file). The tutor may read another unit of that module when the goal needs it, and says which unit it is using.
3. **The slide panel in Learn.** A question shows the slide it is about. Otherwise the panel shows the latest slide the tutor cited. A slide the student picks holds until the next step arrives. It stays closed until opened (V-57).
4. **Practise questions.**
   - A new prompt on the cheap model: a question stands on its own and may be up to 200 characters, so it can state the example it uses; applied questions first; each wrong option is the right answer with one believable mistake in it, the same length and form.
   - Rule checks in code, free: no pointing at "the lecture", "the slides" or "the example above"; no option that gives itself away by length; no two questions that are the same question.
   - One small second call that is shown only the questions and drops any it cannot answer as posed, or answers differently.
   - A round no longer opens on the easiest five: a lecture's "Practise this", a study block and the hand-off pick by history, as "Practise this module" does.
   - "Rewrite questions" on a module in the Library. Nothing is rewritten otherwise.

## 6. Part B: the Learn session

1. **Start.** The five steps of decision 2. Suggestions come from the student's own module: the session they stopped, this week's unit, ideas to revisit, "work through a sheet". The typed goal and any attachment go to the tutor as the goal.
2. **The check.** Optional. It asks about the ideas the goal needs, basic first, in the student's own words where that fits, and stops at the first one they cannot do. Nothing is marked wrong. It never asks about something the student would need the lecture's own example to answer.
3. **Where you are.** Each idea the goal needs, as a block, basic at the bottom: Solid, Shaky or Not yet. The student can correct any block. The plan is built from it.
4. **Checks.** The tutor asks the student to explain, derive, prove or do the next step; reads what they wrote; says what is right and what is missing. Each idea ends on a problem the student attempts. A written check counts towards Solid and To revisit.
5. **Attachments.** An image or a PDF, at the start or on the line to the tutor: a problem sheet, a worked solution, a photo of working. Kept with that session only. The tutor walks through it, then sets a variation for the student to attempt.

## 7. Part C: after Monday

Streaming the tutor's words as they are written. Visuals shown large, and demos the student can play with. Notes on A4 pages treated as notes: split by their sections, shown as pages. None of these is designed yet.

## 8. How it will be checked

- Tests first, table-driven, for every rule in `src/core/companion/`.
- Every screen at the window sizes in `check-layout` practice: 735 to 1920 wide, 600 to 1000 tall, with the probe for cut, spilling and overlapping content.
- The real AI, on his slides, as few runs as show it works: one study pack rewritten; one Learn session from "What do you want" through a written check; one session asked for another week's material; one with an attachment.
